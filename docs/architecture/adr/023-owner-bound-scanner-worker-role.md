# ADR 023: Owner-bound scanner worker role

Status: worker role, private local CLI enrollment and transactional lease authority implemented. Network/Unix-socket worker transport, actual executor dispatch and receipt ingestion remain unfinished.

Additive migration 6 stores scanner worker identity, owner, SHA-256 credential hash, active/revoked state and expiry. Enrollment requires the durable provisioned-mount owner and at least one connected repository. Credentials are 256-bit random capabilities with a bounded 1–1440 minute lifetime. At most eight live workers per owner and one hundred retained identities exist; expired/revoked identities are not silently reused or rotated. Browser owner sessions do not create worker roles.

The local operator command is `aegisctl scanner-worker enroll ID MINUTES ABSOLUTE_CREDENTIAL_FILE`. The credential file must be new, regular, mode 0600 and under a canonical parent directory; existing files and symlinks are refused. Credential bytes and directory entry are synced before enrollment commits. An audit/delivery failure rolls back the new role, and only the exact file created by this invocation is eligible for cleanup. No token is printed, put in argv, included in general JSON or stored in the database/audit. The host operator remains trusted; this is not protection against an administrator controlling the host filesystem.

`aegisctl scanner-worker revoke ID` withdraws the role and requests cancellation for its running scanner job in one audited transaction. It retains admission and does not assert that a container stopped. Job claims now take explicit worker and owner identities, select only that owner's jobs, and verify live enrollment inside the claim transaction. Renewal also checks live enrollment and provisioned-mount ownership inside its transaction. Thus an authenticated transport request followed by concurrent revocation cannot use stale identity to claim or renew. Public transport must still authenticate the worker capability before invoking these internal operations.

Tests exercise real SQLite enrollment, hashed credential privacy, owner/session-role separation, unregistered/foreign-worker refusal, revocation before claim, running cancellation without cleanup release, expiry of an otherwise live lease, audit-failure rollback, identity/budget limits, private exclusive file delivery and failed issuance. Migration 1–5 bodies remain unchanged. An old scanner request or lease does not grant a new worker role by migration.

No worker-auth endpoint, polling service or scanner HTTP feature is exposed by this increment. Owner-facing scanner API/generated clients, authenticated bounded worker transport, worker loop and private snapshot/executor integration, immutable receipt and finding ingestion, proof of cleanup and admission release remain required. Local CLI acceptance does not prove a scanner ran through the durable queue or complete the v4 isolation/release gates.
