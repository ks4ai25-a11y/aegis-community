# ADR 022: Durable scanner leases and uncertain cleanup

Status: internal controller lease component implemented. Authenticated worker transport, actual scanner dispatch, validated receipt ingestion and confirmed admission release remain unfinished.

Additive migration 5 creates a singleton scanner_dispatch record separate from owner-visible request state. Migrations 1–4 remain unchanged. Claim commits this admission slot, running state and authorization audit atomically. It returns a fresh 256-bit random capability to the trusted worker caller; only its SHA-256 hash is persisted. General JSON serialization and audit records omit the capability. Worker authentication must be established before invoking this internal method; owner sessions cannot substitute for that enrollment.

Claim rechecks the request hash and relational identities, repository ownership, current map digest, trusted tool-lock digest and stored map content digest. Changed source metadata or pins terminates the request as tool_error before any external admission. The returned map is metadata, not a current-byte verification: the isolated worker must still recapture and validate a private snapshot with source.Capture before launching a scanner.

A live lease renews for fifteen seconds, capped by an immutable suite deadline: sixty seconds for bounded capture plus the selected tool count times its requested timeout and five seconds cleanup allowance, capped by the original fifteen-minute request expiry. Worker guards must run throughout capture, tool execution and cleanup. A changed authority, cancellation, forged worker/capability/request identity, expired lease or elapsed deadline refuses renewal. The container PID-1 guard remains an independent timeout boundary; a controller lease is not a substitute.

Queued expiry produces timeout without acquiring a dispatch slot. Running expiry or uncertain failure produces timeout/cancelled/tool_error while retaining the dispatch record as cleanup_required. A terminal job does not prove its container stopped. No new managed job may claim while the slot exists, including after a controller/database restart. Reconciliation processes at most two hundred expired queued records per call and never repeats scanner execution. Identical committed finite-failure finishes are idempotent; differing failure replay cannot rewrite evidence.

This component deliberately has no boolean cleanup bypass, slot release or completed-success operation. The next integration must verify enrolled-worker cleanup receipts against the actual journalled engine/workspace and bind immutable scanner results before releasing admission. This controller-database singleton is not cross-operator host arbitration, a disposable-VM security boundary or independent isolation certification.

Tests use real SQLite for exclusive/concurrent claim, exact map binding, deadline-capped renewal, capability forgery, cancellation, queued expiry, changed map/pins/content, restart lease expiry retaining uncertain admission, finite sanitized failures, idempotent finish and audit-failure rollback of claim/reconcile/finish. No test claims an actual worker executed a scanner through this queue. Scanner API, transport enrollment, worker loop, result/finding storage and UI still remain required by v4.
