# ADR 055: Separate packaged controller-observed daemon authorizer

Status: experimental packaged integration; controller allocation fencing and independent cleanup/release remain unfinished.

## Decision

Package `aegis-engine-authz` in a dedicated scratch target with its pinned scanner lock and owned private channel directories. The disabled `operator-engine-gate` Compose profile runs only `serve-bound`, UID/GID 10001, network none, read-only root, cap-drop ALL, no-new-privileges, bounded memory/CPU/PIDs, no restart and no container logging. Exactly four mounts give it the read-only controller socket, a separate read-only observer credential, the read-only canonical workspace registry at its original host path, and its exclusive writable plugin journal/socket directory outside the registry. It receives no engine API socket/group, TLS client key, worker/dispatch credential, controller database or repository asset mount. The broker/dispatcher do not receive the authorizer's observer capability or state.

This packages ADR 054's existing create/start preconditions. It does not turn the read-only observer capability into a write grant or a cleanup credential. The TLS daemon must separately be configured to use this exact plugin socket and exclude native HTTP/2 bypass as described in ADR 051/052. Selecting a Compose profile does not reconfigure or prove exclusive control of any daemon. Default demo services are unchanged.

## Disposable integration

Keep the previous one-shot, selected-broker and TLS experiments as regressions. Add a separate explicitly enabled GitHub Linux AMD64 run, gated by `AEGIS_PACKAGED_CONTROLLER_GATE_TEST=1` and the existing worker/broker/isolated-engine flags. Its new data/exec roots, unique containerd namespaces, pinned daemon archive, private short-lived TLS hierarchy, removed raw bootstrap listener and fixed opaque relay remain unchanged.

Metadata preflight initially uses the existing unused unbound plugin. After the controller approves the actual TLS engine/registry, journal and selected broker, enroll a separate observer in a nonce-labelled private volume. Stop only the recorded native preflight plugin and retain its unused journal. Initialize a new plugin-owned journal under the approved TLS engine identity, then start the separately labelled authorizer container on the orchestration daemon. It mirrors only the scanner registry read-only, while the broker's authority and mutable work area remain separate. The dedicated daemon reconnects through the same private plugin socket; no raw listener is reopened and no workstation service is selected.

Inspect actual container hardening/mounts and compare the disabled Compose profile. A native CI-only test client, compiled outside the shipped images, uses the broker TLS principal to submit the exact fixed profile under an unregistered name. It requires HTTP 403 and no mutation attempt directory before removing only its denied probe input. An unexpected/uncertain allocation preserves that input. The probe does not print credentials, request bodies or runtime metadata. Its execution requires the explicit Linux CI scope and UID/GID 10001.

The normal packaged dispatch then requires real guarded Bandit execution, committed T0 receipts/results, original-engine child absence, settled broker/plugin journals and the existing queued second-job hold. Afterward, stopping the authorizer must fail closed on a harmless engine read. Starting the used plugin journal through unbound `serve` must exit with the CLI's policy-refusal status; a generic container startup error cannot count as that proof. No mutation retry, namespace reset or cleanup release is introduced. Stop/remove only exact image-and-nonce-checked fixture containers and credential volumes; retain private engine/journal/certificate state until runner destruction. Unknown work preserves controller/worker state rather than declaring cleanup.

## Evidence and limits

The workflow's additional packaged-authorizer step is the actual Linux integration check. `alpha/engineauthz/packaged_real_test.go`, `tests/integration/packaged_authorizer_fixture.py` and the existing packaged-worker fixture contain the assertions. Local validation builds and inspects the scratch image through a stopped nonce-owned container, checks private directory ownership/modes and exact lock bytes, verifies no shell/Docker executable/engine socket, resolves the disabled profile and runs full source checks. Local image inspection alone is not evidence of bound daemon execution. Runtime acceptance payloads remain private; public output contains named test statuses only.

The daemon still relies on the trusted host, responsive local filesystem and point-in-time controller/file observations. Controller state or paths can change after the last observation. Actual daemon fault coverage for cancellation/revocation/file replacement during live execution, durable controller allocation fencing, late-allocation exclusion, independent TLS observation/reconciliation, replacement/recovery and atomic cleanup release remain required. Existing controller/plugin tests cover those refusals at the decision layer but do not prove daemon race exclusion. All-write mediation and cleanup-release flags remain false. Full v4, VM isolation, advisory databases, proof/remediation, desktop AI/MCP and H7 acceptance remain unfinished; public beta remains NO-GO.
