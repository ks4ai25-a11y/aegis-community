# ADR 016: Exact private scanner input and independent execution guard

Status: implemented for an operator-launched offline executor; controller scanner-job orchestration and independent review remain pending.

Scanner findings cannot be tied to an inventory hash while a tool reads a changing host checkout. The shared source layer now captures the exact included file list into a newly created private workspace. It verifies the approved map before capture, each copied file's bytes/hash/size, the checkout again after capture, and the complete resulting snapshot. Stale inventories, changed/extra files, symlinks, cancelled work and scratch directories inside the repository are refused. File/byte/directory bounds from ADR 015 apply. Protected/generated files remain excluded and that coverage limit is disclosed. Captured files are mode 0400 in mode 0700 directories; no source content is retained by default after execution.

A local operator CLI runs only a selected pinned scanner through fixed argv. This executor is not linked into the web controller and adds no Docker socket to it. Docker control remains an explicit local operator privilege. The tool container receives only the private read-only source snapshot, a private read-only rule snapshot when applicable, and a copied read-only guard/manifest directory. It receives no host session, API credential, Docker configuration or user environment. Public images must already be present (`--pull=never`). Inputs are not compiled and repository scripts, hooks and package installers do not run.

Execution profile: non-root UID/GID, all capabilities dropped, no-new-privileges, network none, read-only root/source/rules, one CPU, 768 MiB RAM with no extra swap, 128 processes, 96 MiB noexec/nosuid temporary filesystem, no Docker log storage, at most 120 seconds and 8 MiB per stdout/stderr stream. Bind mounts require source existence rather than silently creating an empty directory on a different daemon host.

An Aegis-built guard is container PID 1. It accepts a finite scanner ID and bounded duration only; it cannot accept an arbitrary command. Before executing the fixed tool, it independently hashes the actual mounted source and rule files against their manifests. It enforces the deadline and stream bounds inside the container, independently of the host worker. Deadline/cancellation kills the child process group; PID-1 exit ends remaining namespace descendants. The host additionally removes the exact randomly named container and confirms its labelled cgroup is absent. Cleanup uncertainty produces tool_error and prevents a passing execution receipt.

Receipts bind input-map and snapshot identity, included files/bytes, tool lock/image/version, exact invocation, guard binary hash, rule-pack hash, elapsed time, exit code, result status and cleanup state. Findings cite snapshot identity and only paths present in that input. Scanner output remains untrusted. The boundary emits normalized findings and bounded package coordinates, discarding raw stdout/stderr. The current Semgrep pack is only the synthetic demo rule. Trivy's default offline profile scans vulnerabilities; configuration review requires a separate consented profile. Missing offline OSV/Trivy databases remain tool_error, never clean zero findings.

The Syft profile accepts the observed pinned CycloneDX 1.7 output as well as earlier known versions. It exports only bounded package coordinates, not arbitrary scanner properties or source snippets. CycloneDX's official version overview is https://cyclonedx.org/specification/overview/ . This coordinate summary is not a claim of complete CycloneDX/SBOM export or publisher authenticity.

Tests cover exact capture, stale/forged maps, tampering/extra files, cancellation, protected-file omission, scratch-path refusal, output overflow, unpinned images, finite guard commands and malformed SBOM coordinates. Real tool acceptance checks both seeded and safe snapshots for Semgrep/Gitleaks/Syft, plus honest OSV/Trivy database failures. Guard acceptance checks timeout refusal and SIGKILL of the host CLI, with inspected network, mount, memory/swap/CPU/process and log settings.

Remaining hard requirements: durable scanner queue/leases and narrowly authorized worker provisioning, crash-journal/workspace recovery, restricted local diagnostic-artifact retention, offline database freshness, comprehensive rule/language coverage, deletion controls, publisher signatures/licence review, independent security review and all H7 release gates. SIGKILL prevents host cleanup defers; private source/guard workspaces therefore require operator cleanup until durable recovery exists. Untrusted application code or patches must still use a separate disposable VM boundary; this executor supplies no such feature.
