# ADR 024: Private authenticated scanner worker transport

Status: Unix-socket transport, local probe and controller wiring implemented. Actual executor worker, immutable result ingestion, cleanup-release validation and owner-facing scanner API/UI remain unfinished.

The scanner worker role is separate from browser sessions. The controller now serves a finite worker protocol on a dedicated Unix listener configured by AEGIS_SCANNER_SOCKET; no handler is mounted on the public dashboard listener. The demo enables /run/scanner/worker.sock in a private scanner_socket volume mounted only into the controller. Its directory is owned mode 0700 and socket mode 0600. No Docker socket or database is supplied to a worker through this interface.

The server requires one exact Bearer capability from local enrollment on every request. Cookie/Origin requests, non-POST methods, query strings, unknown operations and malformed typed objects are refused. Bodies are bounded to 8192 bytes, flat keys must match canonical names, and duplicate/null/unknown fields and trailing documents are refused. Two concurrent requests are admitted; the listener has bounded header/read/write/idle timeouts. Error responses are finite codes without raw source, credentials or database diagnostics.

Identity returns only enrollment metadata. Claim derives worker and owner from authenticated enrollment, then rechecks enrollment inside the queue transaction. The private response explicitly carries the per-job lease capability, job, approved application map and deadline; general Lease serialization still omits the capability. Guard/fail bind the owner-scoped job ID, exact request digest and distinct lease capability. Neither enrollment capability nor owner session can substitute for a lease capability. Failure retains cleanup admission. There is no arbitrary command, URL, path, profile, completion claim or cleanup bypass operation.

The configured tool lock is read from the immutable image copy and validated against the finite six-tool pin catalogue. Its file digest supplies queue authority; target repositories cannot select it. This is pin binding, not publisher signature verification. The controller reconciles scanner expiry once per second even if a worker disconnects, logging only transitions into/out of reconciliation failure.

Socket startup holds a private kernel flock for the listener lifetime, preventing concurrent startup from unlinking another listener's socket. An owned stale socket is removed only after ECONNREFUSED and unchanged file identity; ordinary files, symlinks, unsafe directories and uncertain/live listeners are refused. Kernel leases release on process death. Graceful shutdown closes the listener and removes its own socket. Linux/macOS are supported here; Windows private IPC remains unfinished.

The local `aegisctl scanner-worker probe CREDENTIAL_FILE` reads a bounded owned regular mode-0600 file with no-follow/nonblocking opening, connects only to the configured owned private socket, refuses redirects and caps the response. It prints identity metadata, never credentials. It does not claim jobs or execute scanners.

Tests exercise the real Unix listener and SQLite queue, authenticated claim/guard/finite failure, role/capability confusion, malformed bodies, source/job binding, exclusive socket admission, stale socket recovery, private file handling and pin validation. Live enrollment/probe plus existing repository/crash regressions are recorded separately. These checks do not prove an actual scanner worker consumed a durable job or satisfy independent isolation/release gates.
