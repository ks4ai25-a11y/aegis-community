# ADR 027: Shared scanner receipt data and validation boundary

Status: accepted as the contract foundation for controller ingest. Durable ingest and scanner job completion remain unfinished.

Scanner receipts must be checked by the controller without importing the privileged executor. `aegis.local/source/scanevidence` defines the existing parser 1.2 provenance, finding, result, invocation and execution data. The alpha parser and executor expose type aliases, preserving their existing JSON shape. Fixed invocation construction and the 8 MiB limit are shared, so a future controller receipt check uses the same finite argv contract as execution. This package contains no process execution, Docker access, database access or network client.

`Decode` rejects duplicate and case-fold-equivalent keys, escaped duplicates, noncanonical field aliases, unknown fields, null values, invalid UTF-8, trailing JSON, excessive nesting, excessive token counts and oversized strings/arrays/receipts. SBOM raw JSON has a separate canonical finite schema, limited to CycloneDX format/spec/version and bounded package coordinates. Arbitrary SBOM metadata is rejected. Source snippets and raw matched credentials have no dedicated receipt fields; free presentation text is discarded during normalization.

`Normalize` requires trusted expected application/repository, requested finite tool set, tool version/image, lock digest, requested timeout, owner-authorized map and start/end time bounds. It checks the fixed network-none invocation, profile, parser identity, snapshot and map hashes, exact captured-file list, included byte count, source paths, container/guard/rule digest formats, exit/result/cleanup consistency and partial diagnostics. A receipt from an unrequested tool is rejected even if its pin is valid. Preflight failures may truthfully report no container and unconfirmed cleanup; they cannot carry findings or an SBOM.

Findings must reference captured files, retain T0/suspected/low-confidence classification, cite matching tool/version/image/parser/input provenance, and match their static/dependency identity hash. Duplicate IDs, unsupported configuration claims in this offline profile, cross-repository sources, inconsistent aggregate severity, malformed dependency coordinates and proof promotion are refused. Free summaries, coverage strings, diagnostic messages and limitations are replaced by finite text. Structured provenance is retained, caller objects remain unchanged and normalization is idempotent. No partial receipt is returned on validation refusal.

No trusted advisory database freshness manifest exists yet. OSV/Trivy `completed` receipts therefore normalize to `completed_stale_db`, with an explicit unproven-freshness limitation. Incomplete coverage stays incomplete. This classification preserves static advisory claims without suggesting current advisory coverage or verified exploitability. Freshness provisioning and independent provenance must be implemented before admitting a fresh-database completion claim.

Container, guard, rule and cleanup fields are bounded worker claims. Format checks do not verify publisher authenticity, independently attest the guard/rule pack, prove process absence, prove workspace destruction or authorize an evidence tier. A `cleanup_state: complete` field alone must never release controller dispatch admission. Likewise, validation does not authenticate a worker, authorize a lease, persist a receipt, complete a job or approve an owner-facing result. The future ingest transaction must enforce those boundaries independently.

Tests cover identity/coverage/proof refusals, canonical JSON/SBOM hostility, privacy projection, preflight/partial failures, requested-tool selection and stale-database classification. A component integration test obtains a real six-tool owner-authorized controller claim and passes fixture outputs through all six actual alpha parsers, shared decode and normalization with pinned version/image metadata. It confirms source binding, T0 classification and omission of arbitrary messages and synthetic matched-secret text. It does not run scanner images or repository code.

Remaining required integration is the controller's append-only receipt ledger, authenticated bounded ingest endpoint, replay semantics, owner-bound reads, actual worker execution loop, independent cleanup confirmation, database freshness provisioning, deployed acceptance and the rest of the v4 manual. This contract does not satisfy those requirements by itself.
