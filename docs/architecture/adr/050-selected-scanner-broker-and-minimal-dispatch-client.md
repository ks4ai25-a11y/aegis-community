# ADR 050: Selected scanner broker and a minimal private dispatch client

Status: implemented experimental broker/client boundary; independent cleanup release unavailable.

## Decision and authority

Move privileged orchestration into a dedicated `aegis-scanner-broker` process. Its scratch image contains the fixed broker binary, pinned rules/tool lock and both guards. A separate scratch image contains only `aegis-scan-dispatch`. The dispatch container receives two read-only private volumes: its limited credential and the broker Unix socket. It receives no daemon socket/group, worker enrollment credential, controller socket/database, source assets, workspace registry or journal. Neither image contains the research operator CLI or a shell.

The broker alone receives the operator-provisioned daemon, private worker channel/enrollment, approved read-only assets and canonical mirrored work root. It executes the existing bound worker path with original engine/registry/journal checks, exact fixed scanner plans, independent child guard and durable RPC uncertainty journal. Both containers use a positive UID, network none, read-only root, capability drop and resource limits. The broker remains a privileged trusted component because its daemon socket grants broad engine authority.

Add a separate immutable controller-local broker binding referring to the existing journal approval and one active enrolled worker ID. Initial `aegisctl scanner-engine bind-broker WORKER_ID` requires the full prior chain and no dispatch slot, and commits approval/audit together. Exact replay returns the original record; replacement/reset is unavailable. Configured claims and live authority checks reject other enrolled workers before admission. The broker verifies its selected identity through a bounded authenticated private read before claiming. Restore removes this binding and revokes enrollment while preserving history and cleanup holds. No database migration is added. Legacy unconfigured experimental paths remain explicitly unmediated.

## Private protocol

The finite authenticated protocol accepts only `POST /internal/v1/scanner-broker/run-once` with an empty JSON object. It accepts no owner, tool, path, image, command, URL or request-forwarding parameters. Browser cookies/origins, query/encoded-path variants, extra authentication, compression and malformed/oversized payloads are refused. Credentials are new private exclusive mode-0600 files inside canonical owned mode-0700 directories, never argv/env token values. The broker rereads capabilities per request and refuses the same capability for its dispatcher and controller-worker roles. Withdrawal prevents subsequent dispatch; it is not proof an existing run has stopped.

The handler serializes execution, bounds accepted connections to eight, headers to 8 KiB and request bodies to 512 bytes with a five-second read deadline. A dispatch has a fifteen-minute ceiling; original shorter controller/guard budgets still apply. Responses contain only bounded state, job/request/result digests, receipt count and conservative false authority flags. No source, finding body, raw tool output or enrollment/lease token is returned. The client uses only a direct Unix transport, rereads private state and rejects redirects, ambiguous/noncanonical responses and bodies over 4 KiB. Its dependency graph contains no engine SDK, executor, worker or controller package.

An exclusive process lock prevents another listener replacing a live broker. A stale socket is removed only after an owned-inode check and refused-connect observation under that lock. HTTP listener closure stops new work but retains the process lock until cancelled worker work has joined; shutdown has a separate twenty-second budget. If shutdown remains uncertain the process fails and existing durable admission/journal quarantine remains. There is no auto-retry, restart loop, namespace reset or cleanup-release RPC.

## Validation and remaining work

Tests challenge private token permissions/link/FIFO/withdrawal paths, stale/live sockets and lifetime locks, finite request boundaries, concurrent requests, bounded connections, cancellation join ordering, errored-run success refusal, redirects/truncation/oversized replies and false authority claims. Controller tests cover immutable/restarted/concurrent broker selection, denied-worker non-consumption of admission, corrupt/missing parent state, audit rollback and restored authority invalidation. A nonce-owned packaged fixture checks actual broker/client mounts and Compose separation, denies a second enrolled worker and dispatch-capability substitution, runs real tools through the limited client, compares owner results and retains the second-job cleanup hold. Existing one-shot acceptance remains a separate supported experiment.

This separates the dispatch client from scanner authority and constrains normal controller execution to the selected broker. It does not prove exclusive mediation of every daemon client, prevent host-admin tampering, authenticate independent cleanup, exclude all active leases/incomplete allocations/late starts, or supply the disposable VM boundary for arbitrary repository code. The broker is still trusted and has raw engine access; all-engine-write and cleanup-release flags remain false. Enrollment expiry/revocation stops new work, while safe binding replacement and recovery remain unfinished. Public beta and full v4/H7 acceptance remain NO-GO.

## Observed local evidence

`docs/evidence/scanner-broker-acceptance.json` records repeated race coverage (54 controller, 633 broker/worker-channel and 57 private-IPC/client pass events), full source checks and vet, native builds, actual schema checks and the dispatch dependency graph. `docs/evidence/broker-dispatch-acceptance.json` records sixteen actual six-tool broker/client checks, source-bound owner results, immutable broker selection, minimal read-only client mounts, wrong-role/worker refusal and verified nonce-owned resource removal. The existing one-shot worker separately passes fourteen packaged regression checks. Missing offline advisory databases remain tool errors and static findings remain T0. These are automated/local reference checks, not independent installation or security sign-off.
