# ADR 025: Scanner-side private client and claim validation

Status: accepted for the Linux/macOS alpha worker foundation; execution-loop integration remains unfinished.

The scanner executor must consume owner-authorized jobs without reading controller state or accepting browser credentials. `alpha/workerchannel` implements the four finite operations on the dedicated Unix worker listener: identity, claim, guard and failure. It does not import the controller, open its database, launch tools, ingest results or release cleanup admission.

An operator constructs the client with explicit canonical local socket and credential paths, expected owner and trusted local tool-lock digest. The socket must be owned by the current UID, mode 0600, under a canonical owned 0700 directory. Credential reads use nonblocking no-follow descriptors and confirm regular-file identity, UID and mode 0600. The client rereads the capability for every operation and rechecks the socket before each connection. HTTP proxy discovery and redirects are disabled; request destinations are fixed and the transport dials only the configured Unix path. Same-UID host compromise remains outside this local isolation boundary.

Claim acceptance recomputes the typed request hash and application-map content hash, checking schema, owner, pins, application, repository identity, finite sorted tool set, source reference, state, cancellation, expiry and deadline. The worker receives no repository filesystem path from this channel; later execution must resolve the registered mounted asset through an operator-provisioned root and capture a validated snapshot. The lease capability is omitted from ordinary JSON serialization.

Responses are bounded to 8 KiB for acknowledgements and identity, and 8 MiB for application-map claims. A token pass rejects duplicate keys (including escaped names), noncanonical field aliases, unknown fields, null values, invalid UTF-8, excessive nesting, excessive token count and trailing JSON before typed decoding. Errors expose only finite local descriptions or HTTP status, never response bodies or capabilities. Guard validates the original claim binding again before requesting renewal. Failure uses only the three finite server-supported codes; a failure acknowledgement must retain `cleanup_required: true`. Failure replay after the execution deadline is submitted to the server for authoritative idempotence checks and does not authorize continued execution.

Tests exercise real local Unix HTTP connections, hostile responses, claim tampering, acknowledgement mismatches, credential removal, unsafe credentials and socket permissions. They use a protocol fixture, not the deployed controller or scanner tools. Full source checks cover compilation, Go race tests, generated-contract reproducibility and the console build. This evidence does not prove a deployed worker loop, result ingestion, verified cleanup, VM isolation, Windows transport or remote workers.

Next required integration: consume a claim, resolve and capture its owner-bound source, maintain lease guards across execution, cancel on guard failure, submit bounded normalized receipts through controller validation, and retain uncertain cleanup until independently confirmed. No completed scanner state is manufactured by this client.
