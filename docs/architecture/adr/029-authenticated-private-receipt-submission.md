# ADR 029: Authenticated private scanner receipt submission

Status: accepted for the private worker ingest path. The runnable worker, cleanup confirmation and terminal suite aggregation remain unfinished.

The append-only controller ledger is now reachable at `POST /internal/v1/scanner/receipt` on the dedicated Unix worker listener. It is not mounted on the browser-facing HTTP handler. The existing transport authenticates an active enrollment before parsing the body, derives owner/worker from that role, refuses Origin/Cookie headers and query strings, and limits concurrent private operations. The receipt operation requires canonical `application/json` and refuses content encoding.

The shared private envelope contains `schema_version: 1.0`, `job_id`, `request_digest`, `lease_token` and `execution`. `DecodeSubmission` bounds the whole envelope to 8 MiB plus 4 KiB, checks canonical field names and scalar identities, and decodes the execution under the original 8 MiB receipt limit. Duplicate/escaped/case-fold keys, aliases, unknown owner or other fields, nulls, invalid UTF-8, excess depth/tokens/arrays/strings and trailing documents are refused. General serialization omits the capability; only `EncodeSubmission` explicitly produces the private wire representation.

The controller resolves the authenticated owner's job and exact request identity before calling the ledger's transactionally checked ingest operation. That operation rechecks enrollment, original dispatch capability, live authority for new writes, selected tool, pins and map, validates/protects the evidence and commits it with audit. Exact committed replay may succeed after lease expiry; a new expired write cannot. Revoked roles, cross-owner jobs, incorrect capabilities, changed request/pin/receipt identities, unsupported bodies and failed audit writes never persist new evidence.

The acknowledgement contains only schema, job, request, tool, receipt digest, `state: accepted` and `cleanup_required: true`. It does not return source content, raw messages, credentials, the lease capability or a complete-job state. Storage exhaustion returns a finite 429 response; other refusals use finite status/error codes and never return raw SQLite errors.

`Client.SubmitReceipt` verifies the original immutable claim binding, normalizes receipt data before upload, sends only the explicit private envelope and checks acknowledgement fields plus the exact hash of the shared owner/job/request document. It retains the existing file-backed credentials, explicit private Unix path, disabled proxy/redirect behavior, request timeout and bounded strict response parsing. Receipt replay deliberately does not require a still-live original deadline at the client; the controller alone decides whether evidence was already committed. Guard and task execution retain their live-deadline checks.

The six-adapter component test now submits and replays every actual parser fixture through the alpha client and real private Unix HTTP controller handler, then checks six durable owner-bound records, audit consistency and a still-running job. Synthetic container/guard claims are not independent attestation and no scanner image is executed by this test. Additional tests cover wire capability privacy, independently varied acknowledgement mismatches, HTTP replay/expiry, malformed/oversized/encoded bodies, token/request/owner/pin/refusal cases, role revocation and sanitized atomic audit failure.

The local shared-image deployment is updated coherently through the initializer and all dependent services. Doctor and private-worker/repository/scoped-crash journeys verify continuity; no synthetic scan receipt is injected into the live owner's database to manufacture success.

Receipt acceptance does not finish a scan, promote evidence, release dispatch admission or independently confirm cleanup. Remaining work includes actual worker execution/submission lifecycle, independent cleanup proof/release, suite aggregation, owner scanner API/UI, archive rotation, advisory freshness provisioning, deployed real-scan acceptance and the remaining v4 release gates.
