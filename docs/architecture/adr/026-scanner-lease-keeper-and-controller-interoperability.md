# ADR 026: Worker lease maintenance and actual controller interoperability

Status: accepted for the alpha worker foundation. Full tool execution and receipt ingestion remain unfinished.

The scanner-side client must be verified against controller code and durable state, not only a protocol mock. `tests/integration/scannerchannel` is a separate test-only Go module that imports the real alpha client and the controller's internal registry, queue, repository and private transport. Neither production module gains a dependency on the other. The test module's import path is under `aegis.local/controller` so Go's internal-package boundary permits this explicit controller integration test. Production controller builds still do not import the scanner executor or worker client.

Each test opens a fresh migrated SQLite database, connects a fixture repository through the actual owner-bound registry, enrolls a worker through the private credential-file implementation, starts the actual controller handler on its private Unix listener, and performs operations through the actual alpha client. These are in-process real component integration tests, not deployed Compose acceptance and not Docker scanner execution.

The lifecycle test confirms identity, an empty queue, a bound claim, guard renewal, persisted finite failure, idempotent replay, conflicting replay refusal, retained cleanup admission, and audit/capability privacy. Other tests cover owner cancellation, worker revocation, original lease expiry, and mismatched client owner/pins. Cancellation and revocation immediately block renewal and persist cancellation intent; while the original lease remains live, the controller does not assert that execution has stopped. After that lease expires, reconciliation commits cancellation and keeps cleanup admission occupied. The tests observe both states rather than replacing this behavior with an immediate cleanup claim.

`Client.RunWithLease` provides the cooperative worker lifecycle primitive. It validates the original claim and performs a guard before invoking a task. The task context is bounded by the original controller deadline. A joined renewal loop guards every five seconds; refusal or channel failure cancels task authority. The method waits synchronously for the task to return, including its cleanup, stops and joins the renewal loop, and performs a final guard after successful task return. It redacts task errors into a finite sentinel. Parent cancellation and deadline expiration cannot produce success.

A Go context is not a process-kill or VM-isolation boundary. Tasks must honor cancellation and use an independently bounded executor. A task that ignores cancellation remains unfinished; the method does not detach it and report that cleanup succeeded. A nil return means only that the local task and authority checks returned successfully. It does not mark a scan completed, validate a scanner result, ingest findings, release admission, prove cleanup, or authorize a verification tier.

A real private-channel integration test revokes enrollment during a running task, observes the next five-second guard cancel and join that task, and confirms durable dispatch admission remains occupied. Unit tests additionally exercise initial/final guard refusal, parent cancellation, deadline expiration, finite task errors and renewal-loop termination. `make test` now includes the test-only integration module, so hosted source checks exercise this boundary too.

Remaining required work includes the actual bounded scanner execution loop, controller validation of normalized receipts and append-only provenance, verified cleanup confirmation, owner scanner API/UI, independent deployment acceptance, offline database provisioning, and the manual's VM/release gates. These tests do not complete those requirements.
