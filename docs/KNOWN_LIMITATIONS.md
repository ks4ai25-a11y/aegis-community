# Current known limitations

Aegis is an unfinished internal demo preview. Default mode is Observe. The gateway's WAF acts only on HTTP requests passing through its configured route. A matched rule is not proof of a successful exploit; a passing synthetic test is not proof an arbitrary application is secure.

Owner-registered sites (exact host names, private origins reachable from the gateway network) are supported alongside the bundled demo; the isolated preview fixture verifies only the bundled demo controls, not the owner's application. Per-site HTTPS (ACME or local CA) and per-client rate limits are available; trusted CDN proxy ranges and rule-expiry scheduling are not implemented, so behind a CDN every client shares one rate-limit key. Docker origin ports are not published. Only loopback gateway and controller ports are published; this is not a host firewall audit or an HA deployment.

The controller and gateway can fail independently. Controller/collector loss leaves the current gateway policy active. Gateway failure causes an outage; no automatic origin bypass is provided. Gateway restart uses its own persisted active configuration. Controller crash during a leased fixture times out without a passing report. Remaining crash windows, disk-full behaviour, upgrade/restore and volume corruption must pass fault injection before release.

Scanner parsing, owner-scoped read-only repository registration and durable offline scan requests/results exist. Provisioned mounts are bound to one owner; arbitrary browser host paths and remote cloning are unavailable. Current map responses are capped at 60,000 bytes. Pinned Semgrep/Gitleaks/Syft/Bandit compatibility is tested against private snapshots. A native one-shot worker connects the private controller queue, source capture, fixed offline tools and normalized receipt/result ledgers with an independent container deadline guard. The owner API can enqueue/list scans, read admission status, cancel jobs and read immutable T0 suite indexes. The Scans console presents read-only request consent, status, cancellation and static suite summaries. Selected scan results have normalized, conservatively deduplicated finding details and bounded filters/pages. Owner review dispositions are stored separately with immutable revision history; they do not change scanner proof or suppress source claims. The owner Findings catalogue now browses retained scan observations, and source-bound review history supports local export. Cross-revision canonical equivalence, review carry-forward and evidence-backed proof/remediation transitions remain unfinished. A separate opt-in packaged one-shot worker exercises Compose UID 10001 private socket/enrollment pairing without a Docker CLI; background service provisioning and recovery remain unavailable. The packaged profile requires immutable operator engine/registry provisioning and refuses mismatches before claim; configured scope also constrains controller reservation/launch writes. Legacy unconfigured native experiments remain unbound. The orchestrator retains engine authority, its journal root and namespace now require separate immutable controller-local approval, but independent all-engine-write mediation remains unavailable. A fresh namespace cannot inherit approval; incomplete/busy/missing state is refused and the executor rechecks under its lifetime lock. This metadata binding does not attest the host or authorize cleanup release. The operator can observe selected original-engine sandbox metadata and reported host files. A separate scoped private identity can read controller-recorded launch/workspace context; it authenticates metadata origin under local-host trust, not host cleanup. File-based observations retain their false authority flags. Active leases, incomplete allocations and queued late starts remain unexcluded. Independent cleanup verification/release is absent: completed, failed, cancelled and timed-out executions keep admission held. A queued job does not prove a worker is available, and a terminal result does not prove resource absence. Host SIGKILL workspace recovery is available as an explicit journalled operator command and refuses changed engine identity; automatic recovery remains incomplete. Offline vulnerability databases, freshness policy, comprehensive repository/lockfile coverage and user-configurable retention remain incomplete; fixed WAF fixture jobs have durable leases and exact owner-approved scopes. Zero findings never establishes safety. Inventory does not execute repository scripts. Symlinks and oversized input are rejected.

The tenant-isolation challenge uses only bundled trusted code and synthetic users. Arbitrary customer code/patch execution is unavailable until a separate disposable VM boundary exists. Docker isolation alone is not presented as sufficient for that feature. Findings require declared owner semantics and independent verification.

AI is off by default and no provider is required for the demo. Desktop AI pairing, MCP permissions, provider adapters and real provider GUI tests remain unavailable. No raw secrets or repository content are uploaded automatically.

Local tests and hashes are not independent sign-off or publisher signature validation. Public beta is NO-GO until every H7 gate has actual evidence, including independent installation and security/legal review. No production, volumetric DDoS, human-parity red team, exhaustive business-logic, or absolute protection claim is made.

An opt-in journaled local scanner backend records create/start/remove uncertainty across restart; it has a read-only existing-journal status command. It is not an exclusive engine broker or an independently authorized cleanup verifier. Uncertain mutations quarantine that namespace with no trusted repair/reset yet. All controller cleanup admission remains held. See the journaled scanner operator guide and ADR 042.

The database snapshot command captures controller state only. Separate recovery-bundle commands bind schema-13 demo database, persisted gateway policy and trusted scanner lock, restore to a new offline directory and revoke restored authority before startup. An isolated same-engine application drill passes after disposable database loss. This does not establish second-host restore, signed update compatibility, broad disk-full/upgrade fault coverage or independent installation acceptance. See the recovery bundle operator guide.

A separate opt-in dedicated scanner broker now owns the fixed orchestrator, while a scratch dispatch client receives only a limited private credential and Unix socket. Configured controller claims/live authority select one enrolled broker. This does not establish exclusive mediation of every daemon client or independent cleanup release: the broker still has raw engine authority, host-admin trust remains, and safe binding/credential replacement is unfinished. See scanner broker operations and ADR 050.

Behavioural detectors (DET-02…06) record incidents only and can be triggered by crawlers, shared NAT, load tests and deploys. Client and path pseudonyms rotate daily and are held only in gateway memory, so correlation does not span days or gateway restarts.

Incident assessments are advisory. Small local models can be wrong; output is schema-checked and evidence references are validated, but conclusions are not independently verified. A misconfigured remote `AEGIS_AI_URL` would send sanitized dossiers off-host.

Mitigation proposals cover CRS exclusions and Protect only. They must still pass the isolated fixture preview and explicit approval. Connector credentials (MCP) are read-only but can read every site's incidents for their owner.
