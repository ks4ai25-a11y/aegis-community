## Module tests and acceptance scripts

Run module tests from each of `gateway`, `controller`, `alpha`, `shared/source` and `contracts` using `go test -race ./...`; build the console with `npm ci` and `npm run build` in `console`. Run `python3 tests/integration/demo_acceptance.py` against a dedicated demo installation in Observe mode. It temporarily activates Protect, stops the demo controller, restarts the demo gateway and restores Observe. The script creates a demo owner on first use and stores its random passphrase locally with mode 0600 at `/private/tmp/aegis-demo-test-credential`, not in source or reports. Do not use it against an existing user installation.

`tools/scanners.lock.json` pins optional scanner images. `tests/integration/scanner_acceptance.py` runs their read-only static fixture checks with no network or Docker socket. It requires the images to be pulled separately and the `bin/aegis-research` CLI to be built from `alpha`. Semgrep CE, Gitleaks and Syft have local fixture evidence. OSV V2 and Trivy need approved offline database provisioning before known-advisory results are available; missing databases are explicit tool errors.

`python3 scripts/generate_contracts.py` regenerates the current Draft 2020-12 schemas and Go/TypeScript/Python bindings. `python3 scripts/generate_research_api.py` generates scoped Go/Python/TypeScript REST clients from `contracts/openapi-research.json`; the console uses that client. The complete catalogue and remaining API clients are still in development.


The Verify page supports exact scope review, approval, durable fixture jobs, cancellation, revocation and owned report history. `python3 tests/integration/scoped_jobs_acceptance.py` tests these against the named local demo services and kills/restarts only the Aegis controller to check lease recovery. It uses the synthetic demo owner credential created by the earlier acceptance script. Scope grants are fixed to the bundled test_lab and allow four requests total; arbitrary staging targets remain unavailable.

`make test` verifies generated-file reproducibility, module race tests and the console build. CI workflow source is pinned to upstream action commits; an actual hosted CI run and independent installation remain release gates.

The **Repositories** page connects provisioned read-only assets and shows conservative application maps using generated clients. The demo provides `safe` and `vulnerable` static scanner fixtures. See [repository operations](../operators/repositories.md). The owner API can now enqueue/list offline scans, read status, cancel jobs and read immutable T0 suite results through `/api/v1/scans`; see [scanner operations](../operators/scanner-workers.md). The **Scans** page now provides repository/tool consent, job history, cancellation and immutable T0 suite summaries. Selected immutable scans now show normalized finding details with filters, conservative dependency deduplication and original source/receipt identities. Cross-revision finding equivalence/proof lifecycle, background worker provisioning and independent cleanup verification/release remain unfinished. A queued job does not mean a worker is available, and a terminal result does not prove resource cleanup.

An operator-only `scan-offline` CLI captures exact private source snapshots and runs pinned tools behind an independent container deadline/output guard. See [offline scanner operations](../operators/offline-scanners.md). Owners can browse [retained finding observations](../operators/finding-catalogue.md) across scan history, with source-bound review and local history export. An opt-in [packaged one-shot worker](../operators/packaged-scanner-worker.md) now provides private UID/socket enrollment, immutable operator engine/registry and journal namespace provisioning and real static execution without a Docker CLI; missing or changed provisioning refuses before claim, and independent cleanup still holds later jobs. An additional [dedicated broker profile](../operators/scanner-broker.md) limits dispatch to a selected enrolled broker and gives its separate client no daemon, worker credential, source or journal mounts. An [isolated daemon authorization experiment](../operators/isolated-engine-authorization.md) now adds a native deny-by-default Docker policy and a separate durable mutation journal; an additional [TLS broker profile](../operators/tls-scanner-broker.md) connects the packaged selected broker through a credential-free Unix relay and a private mTLS client identity. Controller-authenticated plugin leases and independent cleanup remain unfinished. Independent engine mediation and cleanup release remain unfinished. The opt-in [journaled engine backend](../operators/journaled-scanner-engine.md) records daemon request uncertainty across crashes; controller cleanup admission remains held. The [private database snapshot command](../operators/database-snapshots.md) captures controller state with a bounded artifact receipt. The [recovery bundle commands](../operators/recovery-bundles.md) bind matching demo gateway and tool configuration and restore into a fresh offline directory with restored authority revoked; an isolated database-loss drill validates this reference profile. Complete recovery release acceptance remains unfinished. It adds no Docker socket to the web controller; durable scanner orchestration, host crash workspace recovery and offline advisory databases remain incomplete.

A read-only operator observe-sandbox command can compare original-engine metadata and reported guard/source files with privately exported launch context. It does not authenticate cleanup authority, exclude active leases/late starts or release scanner admission. See [scanner operations](../operators/scanner-workers.md) and ADR 039.

Owner review now records selected-job finding assessments beside immutable T0 scanner evidence. Decisions have exact result/record binding, revision conflicts, durable retry responses and atomic audit history. See [finding review operations](../operators/finding-reviews.md) and ADR 040; cross-job catalogue and verified remediation remain unfinished.

A separate local scanner-verifier identity can now read scope-bound controller launch/workspace context over the private Unix channel. It cannot execute scans or release cleanup admission. See [scoped verifier operations](../operators/scanner-verifier-context.md) and ADR 041.
