# Browsing retained finding observations

Open **Findings** to browse immutable scanner evidence across your owned repositories. Select a repository, category, claimed severity or result-time range. Local date/time fields are converted to UTC API timestamps. The start is inclusive and the end exclusive; the end must follow the start. Page sizes are two, ten or twenty records. Each page shows observations from one exact scan with source snapshot and job identities, original tool versions/receipts, separate owner review, and partial/stale/tool-error flags.

Use **Next retained observations** to finish that scan's finding pages and then visit the next retained scan. Results are ordered newest first by actual timestamp and job ID, including fractional seconds. An empty filtered scan still shows coverage and may have continuation to other retained scans. **Refresh catalogue from first page** restarts after filter changes or a changed retained-result set. Use **Open this scan result** for the exact original Scans detail view. Review controls and private local history/export use the same owner-scoped ledger described in [finding reviews](finding-reviews.md).

The retained-result count describes stored scan results in the selected repository/time range. It is not a count of vulnerabilities or proof of whole-corpus validation. Each selected page revalidates its source evidence. Jobs without an immutable result are counted separately across all times in the selected repository scope, since they have no result timestamp to filter. Missing execution, cancellation, tool failures and stale data do not establish a clean repository. Repeated observations across scans and different source snapshots stay separate; no global vulnerability total or cross-revision review carry-forward is inferred. Owner assessments preserve the original T0 evidence tier.

## Owner API and limits

GET `/api/v1/findings/catalogue` requires an owner session. Optional query fields are `repository_id`, `category`, `severity`, `since`, `until`, `limit` (1–20) and `cursor`. Times use RFC3339 with explicit offset, normalized to UTC. Unknown/repeated fields, invalid time ranges and malformed coordinates are refused. An unowned repository is unavailable. Browser-selected owner identities and execution parameters are unsupported.

`FindingCataloguePageV1` binds the owner and `retained_static_observations` scope, metadata `result_set_digest`, retained result count, missing-result job count, selected result index, original suite and exact finding page, plus an opaque continuation. A zero-result response omits suite/findings instead of inventing a successful scan. The cursor binds the owner, normalized filters and page size, entire ordered retained result roster, result position and inner finding cursor. It grants no authority: every request checks ownership and evidence again. A newly completed result changes the roster and returns HTTP 409 `CATALOGUE_CHANGED`; restart from the first page. Pending jobs and owner review changes can update their own read-time metadata without rewriting immutable result identities.

The catalogue reaches every retained job (up to the 10,000-job budget) rather than truncating at the Scans screen's latest 100. Metadata traversal, selected evidence aggregation and response sizes are bounded; requests have a five-second context and a 120 KiB response ceiling. Oversized or corrupt evidence returns an error and is never silently skipped. Only one result's source evidence is loaded per page. The browser refuses mismatched scope, result/page identities, provenance, review chains or continuation, and drops late responses after filter changes.

This read-only workflow does not start scanners, resolve findings, approve policies, release cleanup admission, export source to a provider or install a background worker. The global canonical finding graph, cross-snapshot matching, evidence-backed remediation/reproduction, broader retention and independent v4 release acceptance remain unfinished. No database migration is needed for this increment.

See [ADR 046](../architecture/adr/046-owned-retained-finding-catalogue.md) and [observed acceptance evidence](../evidence/finding-catalogue-acceptance.json).
